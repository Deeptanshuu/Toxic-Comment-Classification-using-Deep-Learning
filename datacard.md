# Data card: Multilingual Toxic Comment Dataset

A short reference card. For the full pipeline, the split-hygiene measurements, and how the training
loop consumes this data (with worked explanations of every number below), see
**[docs/DATA.md](docs/DATA.md)**.

## Summary

| | |
|---|---|
| Task | Multi-label toxicity classification. "Multi-label" means each comment gets its own independent yes/no answer for every label below — it can be several at once, not exactly one. |
| Size | 356,580 comments |
| Languages | 7 — English, Russian, Turkish, Spanish, French, Italian, Portuguese |
| Labels | `toxic`, `severe_toxic`, `obscene`, `threat`, `insult`, `identity_hate` (binary, non-exclusive) |
| Splits | train 285,264 · val 35,658 · test 35,658 (80 / 10 / 10, stratified by language and label combination) |
| License | Not specified anywhere in this repo. The English base data derives from Jigsaw/Conversation AI's Toxic Comment Classification dataset; the license terms of the 7-language extension are not documented here. |

## Provenance

```
raw 7-language CSV -> cleaned/processed CSV -> + synthetic augmentation (rare classes)
  -> exact-hash dedup -> stratified 80/10/10 split -> train.csv, val.csv, test.csv
```

The script that produced the original 7-language corpus from the base Jigsaw English data is not
included in this repository, so that step is not reproducible from here. Everything from the
processed CSV onward is in `utils/split_dataset.py` and `augmentation/`. Full pipeline diagram and
file references: [DATA.md § Provenance](docs/DATA.md#provenance).

## Collection and labelling

- **Base data**: comments with 6 toxicity labels, extended across 7 languages. The original English
  labels come from human annotation (Jigsaw/Conversation AI). How the labels were produced or
  verified for the other 6 languages is not documented in this repo.
- **Synthetic augmentation**: the two rarest labels (`threat`, `identity_hate`) were topped up with
  roughly 500 comments generated by Mistral-7B-Instruct-v0.3. These rows are **weakly labelled**:
  the label is whatever the generation prompt asked for, not something confirmed by a human or the
  original annotation process reading the output. A lightweight classifier filters obviously broken
  generations, but it was trained on the same distribution it filters, so it cannot catch outputs
  that share the generator's own biases — see [DATA.md § Augmentation](docs/DATA.md#augmentation)
  for why that's circular, not just imperfect.

## Composition

| Label | Positive rate (train) |
|---|---|
| toxic | 49.6% |
| insult | 28.6% |
| obscene | 24.2% |
| identity_hate | 5.3% |
| severe_toxic | 4.6% |
| threat | 2.1% |

One label is close to a coin flip; the other five are rare, and `threat` is rare enough that a model
predicting "no" every time would be right 97.9% of the time. See
[DATA.md § Class imbalance](docs/DATA.md#class-imbalance) for why that makes accuracy the wrong
metric here.

## Known limitations

| Limitation | Detail |
|---|---|
| Class imbalance | See table above. |
| Near-duplicate leakage | 3.8% of English val rows (0.6% of Russian) are near-duplicates of a train row, because augmentation ran before the split. Val metrics on those two languages are mildly optimistic. |
| Weak, circularly-validated labels | The synthetic `threat`/`identity_hate` rows above are not independently verified. |
| No documented license or consent process | Inherited from the upstream sources; not resolved in this repo. |
| No identity/demographic metadata | Beyond `identity_hate` as a yes/no label, there is no annotation of which identity group, if any, a comment targets. |

## Intended use

Built as a learning project to practice multilingual, multi-label text classification. Reasonable
uses: coursework and research on multilingual toxicity classification, studying how class imbalance
and data leakage show up in a real pipeline, benchmarking model architectures on a multi-label task.

**Out of scope**: production content moderation, any decision affecting a real person (account
action, visibility, legal process), or treating the synthetic `threat`/`identity_hate` rows as
verified ground truth. See [docs/KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md) for why the trained model
itself should not be relied on beyond this project's own learning purpose.
